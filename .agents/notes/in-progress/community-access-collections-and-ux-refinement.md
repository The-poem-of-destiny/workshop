## 背景与需求汇总

围绕上线前的社区准入秩序、创作者防呆体验、作品组织能力以及高分辨率显示器下的浏览感受，本轮确认并集中交付以下七项改进：

1. **低调放置社区 Discord 服务器链接（`https://discord.gg/KNy8yV5w44`）**：不在首页首屏显眼处张贴招揽无关流量，仅在用户遇到实际准入/访问阻碍或主动查阅帮助时提供（OAuth 验证因未进服务器或缺少身份组失败时、点击项目的「Discord 讨论」时的跳转提示浮层、以及顶栏低调的「常见问题 / 帮助」弹窗内）。
2. **用户政策同意记录、版本号与 3 道单选题准入机制**：
   - 所有用户须在服务端持久化记录同意政策的版本号与时间；旧版及导入账号全部为空，须重新同意当前政策版本。
   - 政策条款沿用既有三项免责声明（用户内容责任、使用风险自担、条款变更）并补充准确的酒馆安装机制说明。
   - 勾选同意后须通过 **3 道单选题**（问题处理联系模组作者、官方不对模组内容和质量担责、安装以追加模组条目方式进行且更新替换实例条目故操作前应自行备份）。未完成同意及全对答题前，账号仅允许以**游客身份只读浏览**，后端统一拒绝一切需登录的取件、预览、互动、创作与管理操作。
3. **审核流程作者回退与防误删项目交互重做**：
   - 在项目编辑器顶部的「正在审核」横幅直接提供**「撤回审核并继续修改」**一键操作（串联撤回待审快照与基于当前内容创建新工作版本），线上已公开旧版本不受影响。
   - 根治 Legacy 及现版编辑器右上角易误触「删除项目」的问题：移除右上角删除按钮，在编辑器底部设立折叠的「项目可见性与危险操作」专区，优先引导「设为仅自己可见（暂时下架）」，永久删除采用需手动输入项目标题匹配的红色确认弹窗。
4. **引入项目合集（Collections）及复用筛选管线的合集展示页与作者作品展示页**：
   - 作者可创建、编辑、删除自己的合集，并将自己名下的项目加入一个或多个合集。
   - 项目详情页展示所属公开合集并可点击进入合集展示视图；点击作者名称进入作者作品展示视图（含作者公开合集入口）。
   - 合集展示视图与作者作品展示视图直接复用 `/api/v1/projects` 的分类、标签、搜索、排序与分页筛选管线，不维护第二套列表实现。
5. **2K 与带鱼屏弹性自适应卡片网格及酒馆内嵌窗口扩容**：
   - 解决 2K 显示器（2560×1440，100% 缩放）下一行挤出 6～7 张细碎卡片的问题，同时**不死锁最大 4 列**以免浪费 21:9 带鱼屏空间：通过放大卡片基准最小宽度、网格间距、内边距与字号，使 1080p 自然呈现 4 列、2K 自然呈现 4～5 列、带鱼屏自然舒展为 7～8 列。
   - 将 SillyTavern 内嵌弹窗宽度从硬编码 `1200px` 放宽为弹性宽屏尺寸。
6. **消除首页沉闷压抑感并理顺首页布局逻辑**：
   - 修正「左侧筛选栏并排挤压发现栏，但筛选只控制下方列表」的层级错位：将「发现 · 试试看~」提升为全宽首屏舞台（支持折叠收起），下方设立独立的「全部作品」目录区（左筛右列，移除侧栏重复的排序与视图切换控件）。
   - 优化暗金主题的明度对比、顶部微光氛围、单行紧凑顶栏与版块留白节奏，摆脱灰暗局促的后台表格感。
7. **补齐代码审查发现的前后端断头路**：
   - 修复嵌入（`device`）与弹窗（`browser`）模式下 Discord OAuth 验证失败不回传原因或轮询空转 10 分钟的缺陷；
   - 在作者编辑器中补回已实现后端契约的 2 张画廊附图（`gallery_1` / `gallery_2`）上传与删除入口；
   - 在管理后台「项目索引」补齐 Owner 查看详情、一键下架（设为私有）/恢复公开与删除项目的管控操作；
   - 将管理后台「站点设置」升级为结构化的社区邀请链接与公告配置表单；
   - 优化「已安装」列表，改显人类可读版本号并支持「仅看可更新」筛选。

## 核心架构与契约决策

### 1. 社区邀请链接配置与低调披露边界

- 默认社区邀请链接为 `https://discord.gg/KNy8yV5w44`，支持由 Owner 在 `site_settings`（`siteContent.communityInviteUrl`）中覆盖或更新，仅接受 `https://discord.gg/...` 或 `https://discord.com/invite/...` 规范格式。
- **不披露位置**：顶栏、侧栏、首屏横幅与页脚均不直接展示服务器邀请按钮。
- **披露触点**：
  1. OAuth 登录因「不在允许的 Discord 服务器中」或「缺少允许的 Discord 身份组」被拒时，在回调错误页与主界面错误提示中展示入服引导链接；
  2. 用户点击项目卡片菜单或详情页的「Discord 讨论」时，弹出轻量跳转提示层，主按钮前往讨论帖，辅助提示提供「尚未加入服务器？先加入社区服务器」链接；
  3. 顶栏「帮助 / 常见问题」弹窗内的排障折叠问答中提供链接，并支持随时查阅《使用政策与免责声明》。

### 2. 政策版本、准入问答与后端会话门禁

- **数据表结构**：`users` 表新增 `policy_accepted_version TEXT` 与 `policy_accepted_at TEXT`，约束 `(policy_accepted_version IS NULL) = (policy_accepted_at IS NULL)`。历史与迁移账号均初始化为 `NULL`。
- **单点权威定义**：`@workshop/domain` 定义 `CURRENT_POLICY_VERSION = "2026-11-v1"`、政策正文条目与 3 道单选题题库及服务端判卷函数：
  1. **问题处理途径**：使用模组遇到报错、冲突或内容问题时 → 查看模组说明并联系该模组作者反馈，或先自行卸载该模组。
  2. **内容与质量免责**：关于模组内容与质量 → 模组均由分享者本人负责，官方虽设审核机制，但不对模组内容、质量及使用后果承担责任。
  3. **酒馆安装与备份机制**：关于安装、更新与卸载 → 安装会向目标世界书或当前角色追加该模组的条目；更新该实例时会整体替换其模组条目（不保留对该模组条目的本地修改），操作前建议自行备份角色卡与世界书。
- **契约与权限强制**：
  - `GET /api/v1/me` 返回 `user` 与 `policy: { currentVersion, acceptedVersion, acceptedAt, accepted }`。
  - `POST /api/v1/me/policy-acceptance` 校验 `version === CURRENT_POLICY_VERSION`、`agreed === true` 且 3 题答案全部正确后，更新 `users` 记录并写入 `member.policy_accept` 审计事件。
  - **后端铁壁门禁**：凡 `accepted === false` 的会话，除 `GET /api/v1/me`、`POST /api/v1/me/policy-acceptance` 与 `DELETE /api/v1/sessions/current` 外，所有需登录接口（下载/安装票据 `acquisitions`/`downloads`、登录正文预览 `preview/:kind`、点赞/订阅/推荐/版本备忘、个人项目与创作送审、合集写入、审核与管理接口）一律在服务端拦截并返回 `403 forbidden`（`policy_acceptance_required`），确保未通过问答前在系统边界上严格等价于只读游客。

### 3. 合集模型与目录筛选管线复用

- **数据表结构**：
  - `collections(id, author_id, title, description, created_at, updated_at, deleted_at)`；
  - `collection_projects(collection_id, project_id, position, added_at)`，联合主键 `(collection_id, project_id)`。
- **所有权与可见性不变量**：
  - 作者只能创建归属自己的合集，且只能将 `projects.author_id === collections.author_id` 且未删除的项目加入自己的合集（Owner 具备管理权限）；
  - 公开读取（项目详情所属合集、`GET /api/v1/collections/:id`、`GET /api/v1/authors/:id`）仅计入并展示**未删除且包含至少 1 个公开已发布项目**的合集，合集内的私有或未发布草稿项目在公开查询中自动过滤，不泄漏未审草稿。
- **筛选管线复用**：
  - `GET /api/v1/projects` 扩展可选参数 `collectionId`，与既有 `projectType`、`includeContained`、`tag`、`authorId`、`search`、`sort`、`period`、`cursor` 完全正交组合，并在 `cursorScope` 中纳入 `collectionId` 防止跨集合游标串用。
  - 前端通过目录顶部的「作者作品横幅（含公开合集切换排）」或「合集专题横幅」承载上下文，下方直接复用同一套 `WorkshopCatalogue` 与筛选控件。

### 4. 审核回退、防误删与界面布局准则

- **撤回并继续修改**：前端在审核中横幅提供一键操作，确认后按序调用 `withdrawSubmission` 与 `createVersion`（若撤回成功但创建新版本因网络中断失败，保留已撤回状态并明确提示点击新建版本，不伪造跨请求原子事务）。
- **防误删保护**：移除编辑器标题栏右侧删除按钮，沉底至折叠危险区，优先展示「设为仅自己可见」快捷开关；永久删除必须手动输入完整项目标题一致后方可提交。
- **弹性卡片网格**：不设置硬编码列数上限或窄容器锁死，采用约 `350px–360px` 最小列宽与 `24px` 间距（窄屏自动回退双列紧凑布局），兼顾 2K 屏（4～5 列舒展排布，消除 6 列拥挤感）与带鱼屏（自然扩展列数）。

## 考虑过的替代方案

1. **在前端本地 `localStorage` 记录政策同意与答题状态**：拒绝。本地存储无法跨设备同步、无法证明账号本人已完成准入问答，且可被任意请求绕过后端接口；必须在 D1 `users` 表持久化并在后端鉴权边界强制执行。
2. **未通过政策问答前不签发 OAuth Session**：拒绝。若不签发会话，用户刷新页面或提交答题时无法安全绑定 Discord 身份，且需要额外发明一套半登录临时令牌；复用正式不透明会话并在后端按 `policy_accepted_version` 强制降级为只读游客最简洁可靠。
3. **为合集页与作者主页单独开发独立分页列表组件与专用筛选接口**：拒绝。会复制一套搜索、六分类、12 组标签与周期排序逻辑；在 `/api/v1/projects` 增加 `collectionId` 过滤并在目录上方挂载上下文信息头，即可零冗余复用全部检索能力。
4. **用 `grid-template-columns: repeat(4, 1fr)` 或 `max-width: 1440px` 硬限制最多 4 列**：拒绝。会在 21:9 带鱼屏与 4K 显示器两侧留下巨大空白；提高单卡最小基准宽度与内外间距即可在 2K 屏自然呈现 4～5 列，同时允许超宽屏自然延展。

## 后果与风险

- **全员重签影响**：上线切换后，所有既有用户首次使用安装、点赞、订阅、阅读源码或创作功能前均需完成一次政策勾选与 3 题单选；普通游客浏览目录与摘要不受阻断。
- **Schema 门禁约束**：当前仓库仍处于上线前空库 `0001_initial.sql` 基线阶段，变更同步纳入 `0001_initial.sql`、`tools/check-schema.mjs` 及 `tools/migrate/` 离线迁移与校验脚本；真实远端数据库切换仍受既有部署门禁保护，不在本分支直接触碰线上 D1/R2。
- **公共缓存一致性**：新增的公开合集与作者摘要接口遵循现行分类 TTL Cache API 策略（60 秒公开投影），合集变更后在缓存有效期内允许短暂陈旧，不影响私有授权边界。
