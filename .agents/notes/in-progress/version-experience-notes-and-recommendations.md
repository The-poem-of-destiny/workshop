# 版本体验备忘与用户推荐方向

- Status: in-progress
- 日期：2026-10-28
- 决策人 / 产品负责人：用户
- 范围：已确认后续产品方向，尚未实现；本记录不代表当前线上行为。

## 背景与判断依据

旧版评分评价系统试运行期间，2026-10-28 拉取的旧主库中保留了 40 条评分，来自 34 位用户、覆盖 31 个作品，其中 17 条含文字评价。评分分布为 5 分 37 条、4 分 2 条、3 分 1 条。记录创建时间为 2026-10-07 至 2026-10-27；该区间不等同于功能上线时间，记录数也不等同于累计提交次数。

用户判断：当前收集的数据不足，不能据此决定开放评分评价系统。绝大部分为五分，可能说明用户实际想表达的是“推荐”，而非精细的质量评分。这是产品判断与待验证假设，不是已由样本证明的用户动机。

本地原始数据与分享报告位于 Git 忽略目录 `data_backup/legacy-20261028T130040Z/`，不纳入版本库；分享报告为 `旧版评分评价试运行报告.html`，包含完整评价原文和匿名用户编号。

## 已确认方向

### 体验与评分：转向个人备忘

- 后续调整评分系统的描述与定位，转为某种体验备忘系统，而非以公开评价为首要目的。
- 侧重用户为自己记录使用体验和评分。
- 每条体验与评分必须对应某个具体作品版本，不能仅绑定作品而混合不同版本的体验。
- 获得更多数据后，再考虑是否开放这类系统；当前不作开放承诺。
- 具体名称、可见性规则、开放条件及时间尚未确定。

### 推荐：独立承接公开表达意愿

- 后续让登录用户可以推荐自己订阅过的项目。
- 推荐结果反映到发现栏。
- 推荐资格中的“订阅过”按用户原意记录，不擅自收窄为“当前仍在订阅”。
- 不将旧五分记录自动视为用户已作出的推荐。
- 推荐如何影响发现栏的排序、展示、计数及取消推荐规则尚未确定。

## 替代方向与取舍

- 直接延续公开评分评价：暂不采用。当前数据不足，且五分高度集中，尚不足以支持其作为公开评价机制的定位。
- 将体验评分与推荐混为一个动作：不采用。个人版本体验记录与面向发现栏的推荐承担不同目的，应分别表达。
- 立即确定开放条件或推荐算法：暂不决定，避免将尚未讨论的细节变成既定需求。

## 后果与风险

- 后续体验记录的数据契约与界面需要明确作品版本，避免新旧版本评价混淆。
- 个人备忘导向不等同于已经确定具体隐私方案；开放前需要明确用户授权及展示边界。
- 推荐资格依赖订阅历史语义，后续设计需核对现有数据能否支持。
- 推荐高度集中、重复操作和发现栏反馈效应需要在具体方案中评估；本记录不预设解决机制。

## 所属实现与文档影响

- 后端资格判断、持久化及发现栏数据：`apps/worker/`。
- 共享数据契约与产品规则：`packages/contracts/`、`packages/domain/`。
- 界面文案和交互：`apps/worker/` 中对应 Web 实现；具体文件在实施时定位。
- 实施后更新 `docs/` 中对应的当前行为与契约说明；本记录只拥有判断依据与决策理由，不替代实现契约。
- 本决策不替代现有 UI 视觉方向记录，也不授权迁移、公开旧评价或修改远端数据。

## 后续所需验证

- 体验及评分能精确关联具体作品版本，版本变更不导致历史记录被误归到新版本。
- 推荐只能由登录且订阅过该项目的用户作出；明确历史订阅与取消订阅后的资格语义。
- 推荐实际反映到发现栏，且符合后续确定的展示与排序规则。
- 在考虑开放备忘/评分系统前，重新评估新增样本、用户实际用途与可见性预期；不凭本次 40 条记录推断全体用户需求。
