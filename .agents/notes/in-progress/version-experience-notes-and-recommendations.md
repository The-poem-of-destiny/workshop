# 版本体验备忘与用户推荐方向

- Status: in-progress
- 日期：2026-10-28
- 决策人 / 产品负责人：用户
- 范围：版本备忘实现及本地验收由 PR #94 交付；推荐资格按 2026-11-17 最新决定纠正，不据此声明已合入 main 或线上启用。

## 背景与判断依据

旧版评分评价系统试运行期间，2026-10-28 拉取的旧主库中保留了 40 条评分，来自 34 位用户、覆盖 31 个作品，其中 17 条含文字评价。评分分布为 5 分 37 条、4 分 2 条、3 分 1 条。记录创建时间为 2026-10-07 至 2026-10-27；该区间不等同于功能上线时间，记录数也不等同于累计提交次数。

用户判断：当前收集的数据不足，不能据此决定开放评分评价系统。绝大部分为五分，可能说明用户实际想表达的是“推荐”，而非精细的质量评分。这是产品判断与待验证假设，不是已由样本证明的用户动机。

本地原始数据与分享报告位于 Git 忽略目录 `data_backup/legacy-20261028T130040Z/`，不纳入版本库；分享报告为 `旧版评分评价试运行报告.html`，包含完整评价原文和匿名用户编号。

## 已确认方向

### 体验与评分：转向个人备忘

- 体验评分定位为“我的版本体验备忘”：为自己记录使用体验和评分，不向作者或其他用户公开，也不形成公开评分聚合。
- 每条新体验与评分必须对应一个具体作品版本，不能仅绑定作品而混合不同版本的体验。新记录仅针对当前公开发布版本；自己已有的历史版本备忘仍可单独查看、修改和删除。
- 发布新版后，本版备忘从空白开始，不复制旧星级或文字；通过版本选择回看自己的旧记录。评分保持 1–5 星，体验文字上限保持 2000 字符。
- 旧项目级记录没有可靠版本证据，作为“未标版本的旧备忘”原样保留，只能本人读取或删除；不猜版本、不强制归档、不自动变成推荐。离线转换在记录冲突或无法保全时阻断，不丢弃旧记录以继续。
- 获得更多数据后，再考虑是否开放这类系统；当前不作开放承诺，开放条件及时间尚未确定。本次实现不执行真实数据迁移或公开旧评价。

### 推荐：独立承接公开表达意愿

- 登录且当前订阅该项目的用户可以新增或编辑玩家推荐；2026-11-17 的最新决定替代此前“曾订阅过即可”的资格方向。
- 推荐结果反映到发现栏。
- 取消订阅立即失去新增／编辑推荐资格；已有推荐不自动删除，本人仍可撤回。重新订阅后可再次新增／编辑，不从下载、安装或评分推断订阅资格。
- 不将旧五分记录自动视为用户已作出的推荐。
- 推荐如何影响发现栏的排序、展示、计数及取消推荐规则尚未确定。

## 替代方向与取舍

- 直接延续公开评分评价：暂不采用。当前数据不足，且五分高度集中，尚不足以支持其作为公开评价机制的定位。
- 将体验评分与推荐混为一个动作：不采用。个人版本体验记录与面向发现栏的推荐承担不同目的，应分别表达。
- 立即确定开放条件或推荐算法：暂不决定，避免将尚未讨论的细节变成既定需求。

## 后果与风险

- 版本备忘以本人和不可变版本唯一标识关联，并以同项目版本外键防止跨项目混淆；写入实时检查公开可访问边界。缺少可靠版本证据的旧记录与版本备忘分开保存。
- 当前隐私边界明确为仅本人；未来若讨论开放，必须重新确定用户授权及展示边界，不能把本次私人用途视为公开同意。
- 推荐资格以当前订阅关系为准，不保留退订后的资格，也不为此建立历史订阅机制；推荐记录与订阅关系分离，退订不自动删除既有推荐。
- 推荐高度集中、重复操作和发现栏反馈效应需要在具体方案中评估；本记录不预设解决机制。

## 所属实现与文档影响

- 后端资格判断、持久化及发现栏数据：`apps/worker/`。
- 共享数据契约与产品规则：`packages/contracts/`、`packages/domain/`。
- 界面文案和交互：`apps/worker/` 中对应 Web 实现；具体文件在实施时定位。
- 实施后更新 `docs/` 中对应的当前行为与契约说明；本记录只拥有判断依据与决策理由，不替代实现契约。
- 本决策不替代现有 UI 视觉方向记录，也不授权迁移、公开旧评价或修改远端数据。

## 后续所需验证

- 体验及评分能精确关联具体作品版本，版本变更不导致历史记录被误归到新版本。
- 推荐新增／编辑只能由登录且当前订阅该项目的用户作出；验证退订后立即禁用且服务端拒绝写入，既有推荐保留并可由本人撤回，重新订阅恢复资格。
- 推荐实际反映到发现栏，且符合后续确定的展示与排序规则。
- 在考虑开放备忘/评分系统前，重新评估新增样本、用户实际用途与可见性预期；不凭本次 40 条记录推断全体用户需求。
