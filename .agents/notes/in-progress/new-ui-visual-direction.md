# 新站视觉优化：暗金基调与内容型悬浮卡片

- Status: in-progress
- 确认日期：2026-10-23
- 决策负责人：项目所有者；实现负责人：当前前端维护者。
- 生命周期说明：前端已在本地实现并验证，未发布；发布需另行授权。验证范围记录于[界面映射](../../../docs/plans/refactor-2026-10/frontend-fidelity.md)，不代表生产数据等价或公开站点已更新。

## 背景与范围

遵循[双界面迁移决策](dual-frontend-migration.md)，当前只优化新站，不开展经典版迁移，不同步旧站数据，不因旧版缺少功能扩展 API。新站保留自己的首页设计。

用户选择精修现有暗色与金色，而不是换成浅色或重新设计配色体系。用户强调：作图不是二创作者的关键技能，卡片应稍微降低封面占比，给作者介绍 Mod 留出展示空间；卡片采用无边框、阴影悬浮与整卡跟随鼠标轻微旋转。2026-10-24 明确先移除高光，并用 `data_backup` 的真实内容填充本地预览。

## 已确认的局部方向

### 配色与视觉重心

- 保留现有暗色与金色基调，优化层级与质感，不整体更换视觉语言。
- 卡片不以封面质量作为主要展示优势；略微减少封面占比，使 Mod 内容介绍得到稳定展示。
- 作者介绍指项目级 `author_note`，不是作者个人 bio，沿用 D-26 与 D-32 的字段归属，不创建新后端字段。
- 卡片要更有实体质感：无可见常驻边框，以表面和阴影区别背景；整张卡片朝鼠标所在方向旋转小角度，不显示跟随高光。
- 倾斜与阴影参数仍可按阅读效果微调，不将试验值冻结为产品规范。

### 与既有决策的关系

- 对[既有前端决策 D-26、D-27](../../../docs/plans/refactor-2026-10/decisions.md)的卡片视觉部分作局部调整：更重视文字介绍，封面占比及最终尺寸需在本次视觉优化中确定，不把旧 16:9 尺寸要求作为不可调整的验收条件。
- 作者介绍、计数、适配版本、Discord 链接等现有字段归属与数据契约不因此变更；未展示字段的取舍需要明确确认，不静默删除。
- 不恢复旧站首页货架，不重开独立发现页；四项发现栏采用轻量紧凑布局，不抢占主列表的视觉权重。

## 实现选择与可调参数

以下建议已用于本地实现与界面试验；用户确认的是整体方向，不是对每个视觉参数逐项定版：

- 阅读顺序为贴边置顶的直角封面、标题、作者、作者介绍、标签及必要元数据；简介最多两行，采用 12px 正体；标题最多两行，桌面 15px、手机 13px，右侧更多菜单提供查看详情及可选 Discord 跳转。标签固定单行裁掉横向溢出。无独立类型/版本行，类型置于首个标签：角色绿色、扩展紫色、系统核心金色、事件玫红色。鼠标悬停标签区可查看完整标签文本。标题保存上限仍为 200 个字符，展示截断不改变保存值。
- 介绍默认可见，不隐藏到 hover；优先 `author_note`，缺失时回退项目 `description`。有封面和无封面使用一致的信息优先级，不伪造介绍。
- 阴影、轻微抬升与整卡鼠标位置驱动的倾斜共同形成实体卡片感；当前最大约 ±5°，不保留高光伪元素。封面以 16:10 比例随卡片缩放；网格为 >1360px 五列、1181–1360px 四列、641–1180px 三列、≤640px 两列，不设置手机单列断点。
- 卡片底层使用同封面副本，放大 1.4 倍、`blur(24px) saturate(0.8)`、透明度 0.28，上覆不透明度 0.75 的灰色正文遮罩。用户要求提高的是遮罩不透明度，不是图案强度，因此撤回此前图案透明度 0.4 的误解。不使用实时 `backdrop-filter`、滤镜动画或 `will-change`；无封面时保持灰底。卡片外轮廓四角 8px，贴边封面只随顶部外轮廓裁切。统计恢复文字，日期保留 History/Upload 图标，14px、描边 2。静态模糊仍有额外绘制/合成与纹理内存成本，不能据桌面预览宣称低端手机无开销。
- 当前模糊为 16px；更多按钮叠在封面右上，28px 圆形，不占标题宽度；世界书/正则数量和末尾右对齐的版本号合在封面底部深色信息条，上下内边距 2px。正文顶部直角，与信息条贴合，底部仍为 8px 圆角。正文底部仅保留互动统计与日期。无封面时使用紧凑顶部信息栏，不伪造图片。
- 用 DOM/CSS perspective 与 transform 实现卡片倾斜，不为此引入 Three.js；hover 不改变布局占位。
- 标题和内部操作保持可用，键盘焦点清楚。
- 触屏及 `prefers-reduced-motion` 下关闭跟随倾斜，保留静态层次及必要反馈。
- 效果主要用于项目卡片；搜索、筛选、编辑和审核工具保持清楚克制，不全站套用倾斜效果。
- 卡片与页面背景、工具栏及详情一起检查，避免局部动效破坏整体阅读与操作。

## 已确认的整体设计

- 桌面保留侧栏，顶部只承载品牌、搜索和账号操作，不重复放主导航；手机采用固定底栏。
- 搜索留在顶部，类型与排序集中在列表附近；桌面侧栏承载类型，列表保留标签筛选。
- 详情桌面采用大弹窗，手机全屏，关闭后保留来源列表、筛选与滚动位置；从订阅打开详情不切换回工坊。
- 首页四项发现区是紧凑推荐区，不是宣传首屏；手机横向滑动，不纵向堆满四张完整卡片。
- 以上三项整体建议于 2026-10-23 得到用户全部同意。卡片倾斜角度、介绍行数、阴影等仍是视觉试验参数，不因此冻结。

## 替代方案与后果

- 不采用封面主导的作品画廊：用户明确认为 Mod 内容介绍更重要。
- 不在本轮更换暗金基调：用户选择精修现有方向。
- 不以花哨动效替代内容层级：卡片必须在静止、触屏和键盘操作时仍能读懂。
- 降低封面占比不等于进一步随意裁切图片；比例、裁切与无封面状态需要一起检查。

## 验证要求

- 使用实际项目中的长标题、长介绍、有封面、无封面及头像失败状态检查层级与高度稳定性。
- 检查桌面鼠标 hover、内部按钮点击、键盘焦点、触屏及减少动态效果的表现。
- 检查窄屏溢出与横向滚动，不通过隐藏关键内容掩盖问题。
- 浏览器验证只由 subagent 执行；未运行前不声称效果通过。
- 本轮只修改前端与关联文档，不修改后端、数据源或权限语义；无提交、推送或部署授权。
