# 测试准入与维护

目标：用最低长期成本守住可信的行为风险，不追求测试数量、覆盖率增长或每层齐全。AI 生成测试便宜，不代表断言审查、失败诊断、fixture、环境与后续改动便宜。本 skill 是测试取舍的唯一流程；重构组织仍由 autonomous-refactor 负责。

## 1. 先确定风险，不先写测试

读取相关实现、契约、已有用例及实际执行命令。明确：
- 用户可观察的故障是什么、触发条件是什么、后果是什么。
- 哪条产品规则或已复现缺陷支持预期；不能直接把当前实现输出当规范。
- 静态工具、现有测试能否更便宜地覆盖。

完成条件：能用一句具体故障描述说明验证目的，并找到预期的独立依据。没有依据先查契约，不自造断言。

## 2. 默认复用最便宜的有效验证

依次选择，不要求每层都加：
1. 类型／lint／成熟工具可表达的通用约束：复用工具，不逐函数写同义测试。
2. 已有行为测试可覆盖：扩展最接近的边界用例，避免相同路径跨层重复断言。
3. 一次性集成／界面验证：用于当前改动的运行证据，结束删除临时脚本，不自动变成永久套件。
4. 新永久测试：仅当下面准入条件成立。

运行验证不能因“不加永久测试”而省略。类型检查不等于运行验证，单测不等于线上／真实宿主证据。按 AGENTS.md 执行相关命令；不为文档改动启动无关业务套件。

完成条件：选择的验证能触发目标风险，并说明为何更便宜的已有机制不足。

## 3. 永久测试准入

新增前回答四个问题，简单变更可在任务说明中简写，不为每个测试创建文档：
- **捕获什么**：可信、具体的用户可见错误或危险业务不变量，而非“可能有 bug”。
- **为什么新增**：静态检查和已有用例不能以更低成本覆盖。
- **为什么耐重构**：改变文件、私有函数、组件拆分和等价算法后，断言仍成立。
- **如何维护**：fixture 最小、状态隔离、运行确定、失败定位清楚；环境依赖和 CI 耗时与风险相称。

优先保留权限边界、数据丢失、审核／发布状态转换、竞争写入、安装归属与迁移完整性等高后果行为。边界、错误、顺序和并发场景应各有不同故障机制，不堆同路径样例。

完成条件：四问均有具体答案；否则不留下新测试，使用适当临时验证或复用已有检查。

## 4. 写行为证据，不写实现的回声

- 断言可观察结果与禁止发生的副作用；竞争测试同时核对最终状态，不能只看返回码。
- 不测源码文本、导入布局、私有调用顺序、接线／转发、mock 原样回声、固定 UI 文案、偶然默认值、内部结构快照。
- 不以“没抛异常”“非空”“长度增加”代替正确结果；不复制实现算法计算 expected。
- 优先真实纯函数、真实本地存储或协议边界；仅替代不可控外部 I/O。fake 只实现必要真实语义，不复制整套业务。
- fixture 只包含触发风险所需内容；不复用个人数据、令牌、线上状态或跨测试可变资源。
- E2E 只守必要跨边界旅程，不为每个分支复制浏览器流程；语义定位优先，不绑定 DOM 层级。
- 不因 AI 同时生成实现和测试就视为独立验证；预期必须回到契约或缺陷证据。

完成条件：合理内部重构无需重写断言；失败信息能指向一个行为风险；整个套件运行时也隔离、稳定。

## 5. 处理失败与删除负资产

先区分：真实回归、契约有意变化、环境故障、测试脆弱性。读失败证据，不反复重跑已知失败以期待变绿。

- 真实回归修实现；缺陷回归测试仍需经过准入，不是无条件永久添加。
- 有意契约变化，迁移受影响的有效行为测试；不得重新钉住旧实现细节。
- 仅锁定文案／实现／接线、同路径重复或已无消费者的测试，删除而非换个断言继续供养。
- 不稳定测试修隔离／时钟／等待条件；不靠 sleep、自动重试、降断言、skip 或延长超时掩盖。
- 删除有效业务保障必须有契约变化或等价覆盖依据；不能借维护成本删掉正在揭示真实缺陷的测试。
- 不设覆盖率增长、测试数量或每个函数必须有测试的指标；不默认引入全仓截图、变异测试或属性测试平台。

完成条件：每个修改／删除都有分类与依据；仍有效的风险保障未丢失，没有通过降低标准获得绿灯。

## 6. 执行与交付

先运行最相关命令，再按任务／仓库要求做集成验证。修缺陷时保留可行的失败前／成功后证据。临时脚本完成后移除；不把一次性结果说成长期门禁。

报告实际命令、结果、覆盖风险、未覆盖环境，以及新增／删除永久测试的理由。工具门禁与测试都计算配置、CI 时间、误报处理和升级成本，不把生成代码量当成果。

完成条件：证据与最终源码一致，测试留存有收益依据，未执行事项明确，无临时 scaffolding 残留。
