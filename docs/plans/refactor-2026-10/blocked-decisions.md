# 未决事项与阻塞边界

来源：`decisions.md` Q-05、Q-06、Q-10。本文只记录接口准备与不可越界部分，不替技术/产品做选择。

## Q-05 安装状态权威记录（技术，未决）

候选：

1. D1 行
2. 世界书条目内单一记录
3. registry 降级为缓存

当前实现：

- Tavern client 使用脚本变量 `cw_install_registry` 作为**本地安装缓存**，用于展示已安装/版本/卸载。
- 世界书条目写入 `extensions.cw_project_id`、`cw_project_version`、`cw_entry_key`、`cw_installed_hash`，用于识别和保留玩家修改。
- 服务端没有安装状态表；没有把本地 registry 当成权威记录。
- 迁移/修复功能不依赖服务端安装状态。

未实现（必须等 Q-05）：

- 跨设备安装状态同步。
- 以服务端记录判断“已安装/待更新”的唯一真相。
- 迁移工具写入权威安装记录。

可继续实现且不构成选择：读取本地 registry、条目元数据识别、冲突检测、用户手动的卸载/修复。

## Q-06 审核队列读取契约（技术，未决）

候选：

1. 稳定 cursor
2. 短期 snapshot

当前实现：

- `GET /api/v1/admin/submissions` 使用 `submitted_at ASC, id ASC` + base64 offset cursor。
- 这是当前实现细节，不是冻结的稳定契约；并发审核/新提交可能造成翻页漂移。
- 审核详情、diff、报告、重跑不依赖队列游标。

未实现（必须等 Q-06）：

- 对外承诺稳定 cursor 语义。
- 短期 snapshot token/固定队列视图。
- 客户端/第三方依赖队列分页的长期兼容承诺。

## Q-10 每日抽签是否保留（产品，未决）

当前实现：

- 主 UI 不提供每日抽签入口。
- 未新增抽签接口、配额表或定时任务。
- 发现/排行 cron 只构建榜单与 discovery exposure，不包含抽签。

未实现（必须等 Q-10）：

- 抽签接口、配额、前端入口、运营配置。
- 任何“保留/删除”的数据迁移。

以上三项在 checklist 中保持 BLOCKED，不计入“已完成”。实现者不得用默认值、隐藏入口或本地缓存冒充已决策。
