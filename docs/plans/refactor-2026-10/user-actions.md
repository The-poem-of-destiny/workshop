## 1. 凭据与环境：发布前按目标环境核对

旧版本曾配置／验证过某个环境，不表示当前配置仍相同；本次未查询 Cloudflare 运行时或 secrets。变量定义和安全默认值以[运行配置](../../reference/runtime-configuration.md)为准，操作流程以[部署安全规则](../../operations/deployment-safety.md)为准。

| 需要什么 | 用途与边界 |
| --- | --- |
| Discord Application、`DISCORD_CLIENT_ID`／`DISCORD_CLIENT_SECRET`、回调 URI | OAuth 授权与回调；每个实际 origin 单独登记，不能只登记回调就认为整个登录旅程通过 |
| `DISCORD_ALLOWED_GUILD_IDS`、`DISCORD_GUILD_ROLE_IDS` | 公会／身份组准入；按真实允许路径准备正例及不满足任一路径的拒绝账号 |
| `PUBLIC_ORIGIN`、`ALLOWED_ORIGINS`、`SESSION_HASH_SECRET` | 请求与会话边界；按环境核对，production 不复用 staging 会话密钥 |
| GitHub 环境审批、专用 CI 凭据及目标 D1/R2 绑定 | 仅在获授权的环境发布；不得复制本机 `.env` 或个人 token 到 CI |
| 当前 schema 与目标资源核验、可恢复备份及停写／回滚安排 | 真实数据切换的前提；不能用空库 `0001_initial.sql` 更新既有库 |

凭据、Cookie、token、OAuth code 不得写入仓库、测试、提交信息或聊天。真实回调 URL 应由目标环境的实际公开 origin 推导并核对，不沿用本文历史环境值。需要调整 secrets 时由具备权限的操作者按 runbook 执行；本次文档整理未做这些操作。

本地 `preview:debug` 使用隔离的合成账号和短期会话，不需要真实 Discord 回调，也不证明真实 OAuth／公会／身份组已通过。不得用真实用户数据初始化可丢弃验收状态。

## 3. 另获授权后的真实账号与宿主清单

- [ ] 桌面与手机检查目录、分组筛选、搜索、排序、详情、阅读、返回焦点与溢出；显示内容应对应当前目标版本，不以固定项目数为验收标准。

- [ ] 在 ST 嵌入上下文验证提供的登录／设备码旅程，不依赖普通浏览器碰巧已有的会话。

### C. 真实 SillyTavern 安装／更新／卸载

先备份测试角色，使用目标环境对应渠道脚本并核对服务地址；换网页地址不等于脚本已切换环境。角色绑定、登记身份与实际世界书／当前角色正则共同构成证据，订阅或下载不等于安装成功。操作边界见[宿主协议](../../reference/host-protocol.md)。

- [ ] 首次说明、连接与登录可用；选择目标安装实例并先预览、后确认，实际内容写入且重开后仍可扫描识别。
- [ ] 本人修改一条内容后准备新版本，检查整体更新 diff、取消零写入和确认替换；不得未经确认静默覆盖玩家内容，也不假定存在逐条三方合并。
- [ ] 卸载前检查完整实例预览与确认，无关世界书／正则及其他实例不受影响；再次扫描与实际内容一致。
