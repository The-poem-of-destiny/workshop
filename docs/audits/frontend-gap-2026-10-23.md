# 旧站与 staging 前端差距报告

更新：2026-10-23  
范围：匿名线上表面实测 + 当前代码与只读 legacy 代码对照。  
旧站：`https://poemofdestinycreativeworkshop.1528779666.workers.dev/`  
staging：`https://workshop-staging.poem-of-destiny.workers.dev/`

## 结论

当前 staging 不是旧站的表面复刻。用户已确认：staging 未拉取最新数据，数据差异正常；首页差异属于设计变化，不是本轮缺陷。下文保留实测数据，不再据此推定数据源、API 投影或首页设计存在错误。

后续目标已改为经典版前端迁移与新版独立演进，范围与后端边界以[双界面迁移决策](../../.agents/notes/in-progress/dual-frontend-migration.md)为准。当前先搁置经典版，开展新站前端优化；本报告不构成恢复旧功能或修改后端的实施清单。

## 一、匿名线上实测

实测环境为 Chromium，未使用真实登录会话、未输入凭据、未下载或写入线上数据；视口 `1440×1000` 和 `390×844`。以下是线上事实，不是代码推断。

### 已确认的设计与数据差异（非缺陷）

1. **首页信息架构不同。**
   - 旧站：`编辑精选`、`随机发现`、`最新发布`、`最近更新` 横向货架；页面总高约 `1627px`。
   - staging：发现四卡、排序条、类型筛选、项目目录；页面总高约 `1468px`。
   - 判定：用户确认这是首页设计变化，不要求新版恢复旧站货架。

2. **同词搜索结果不同。**
   - 两站输入“学院”并回车。
   - 旧站显示 `456` 个结果（角色 `216`、系统核心 `60`、扩展 `162`、事件 `18`），约 5 列卡片。
   - staging 仅显示 `1` 个结果：`学院扩展角色-时钟塔`。
   - 判定：用户尚未拉取最新数据，本次不按搜索或 API 缺陷处理，不迁移数据。

3. **相同项目的线上元数据不同。**
   `学院扩展角色-时钟塔`：

   | 字段 | 旧站 | staging |
   |---|---:|---:|
   | 版本 | 2.4 | 2.2 |
   | 世界书 | 6 | 4 |
   | 正则 | 0 | 1 |
   | 喜欢 | 34 | 0 |
   | 下载 | 3966 | 0 |
   | 发布日期 | 2026/10/11 | 2026-08-24 |

   判定：用户确认当前数据差异正常。这些数值仅记录实测，不要求为界面优化同步旧站数据。

### P1：桌面界面

4. **详情媒体和布局不同。**
   - 旧站详情 modal：约 `1368×952`，封面约 `857×500`，有“简介／世界书／外链信息” tabs。
   - staging：约 `1408×952`，媒体图约 `898×599`，右栏约 `450px`，没有同等 tabs。

5. **匿名详情的操作引导不同。**
   - 旧站首屏有“已测试最新版”、大号“登录后安装”、Discord 讨论帖、项目资料、评分入口。
   - staging 显示“安装与状态”“尚未安装到当前角色”“请从 SillyTavern 内的按钮打开”，社区获取区没有同等可见 Discord 入口。
   - 这是产品引导和任务路径变化，不只是按钮样式变化。

6. **目录密度不同。**
   - 旧站搜索目录约 5 列，卡片约 `226.8×428.7px`。
   - staging 约 4 列，卡片约 `287.5×283.2px`。
   - 旧站更像发现货架；staging 更像数据目录。卡片封面、标签、安装提示和统计的占位关系不同。

7. **桌面侧栏入口不同。**
   - 旧站：`发现、全部项目、系统核心、扩展、角色、事件`，共 6 项。
   - staging：`全部项目、事件、系统核心、角色、扩展`，共 5 项；发现移到主内容。

8. **顶部工具不同。**
   - 旧站有排序、DLC 管理、Discord 登录。
   - staging 的顶部没有旧站同等 DLC 管理／排序工具组合，品牌标题也进入顶部区域。

9. **卡片信息模型不同。**
   - 旧站主要显示作者、标题、喜欢／下载；标签和安装信息在详情或操作中展开。
   - staging 固定显示类型、版本、标签、世界书、正则、下载、点赞、订阅、更新时间和发布日期。
   - 影响：同屏信息密度、扫描节奏和用户判断依据均改变。

10. **封面裁切和卡片高度不同。**
    旧站使用近方形固定背景封面；staging 使用 `<img>` 与不统一高度的媒体区，竖图卡片更高，网格节奏不稳定。

### P1：移动端

11. **首页方向相反。**
    - 旧站：横向货架，固定约 `65px` 底栏（首页／浏览／搜寻／排序／个人）。
    - staging：单列纵向卡片，无固定底栏；页面 `scrollHeight` 约 `4562px`。

12. **移动详情有实际溢出。**
    在 `390×844` 视口：
    - 旧站封面约 `x=13,w=364,h=204.75`，未发现同类裁切。
    - staging 详情图片约 `x=20,w=446,h=278`，右侧超出视口约 `76px`，截图中已被裁掉。
    - 这是应优先修复的实际移动可用性问题。

13. **移动详情返回和阅读顺序不同。**
    旧站有明确“返回工坊”路径，顺序为标题／作者／类型／标签→封面→简介→版本／统计；staging 使用关闭按钮和 modal 内滚动，首屏顺序及操作位置不同。

14. **移动搜索入口不同。**
    旧站底栏“搜寻”打开标签辅助面板，包含官方标签 chips 和“完成”；staging 搜索常驻 header，筛选／排序条在页面约 `y=1505` 才可见，不能按旧站动作复现。

15. **staging 头像请求失败。**
    实测出现 Discord avatar `ERR_BLOCKED_BY_ORB`，头像节点 `naturalWidth=0`；主要 JSON、封面和列表请求返回 200。它能解释部分头像空白，不能解释搜索结果、布局和项目元数据差距。旧站本次未见对应控制台错误。

## 二、登录后内容：代码静态差距

以下没有登录实测，是 `apps/worker/web` 与 `../workshop-legacy` 的源码对照；不能伪装成线上用户态观察。

### P1：创作者工作区

1. **上传预览与逐项 Checker 反馈缩水。**
   - legacy `upload-preview.ts:290-451` 会展示解析后的条目、文件分组、规则、位置、建议，并支持报告／复制。
   - staging `App.tsx:473-546` 只显示 `empty/checking/pass/warn/block` 和 warning 数，没有逐项预览、报告导出或修复提示。

2. **表单组织缩水。**
   - legacy `project-editor.ts:70-220` 有基本资料、分类／标签分面、封面展示标签和数量提示。
   - staging `App.tsx:700-782` 为平铺字段和逗号分隔 tags，没有分面、展示标签控件或同等输入反馈。

3. **提交前兼容性／原版冲突确认缺失。**
   - legacy `publish-check.ts:70-155` 要求选择适配情况，并在声明原版冲突时选择具体基线条目。
   - staging `App.tsx:594-628` 只运行本地 Checker，然后提交 gate、checker 版本、warning 数和 acknowledged。

4. **发布项目缺少条目级编辑。**
   - legacy 可在编辑界面查看世界书／正则条目并逐条删除（`project-editor.ts:167-180,604-662`）。
   - staging `App.tsx:473-816` 只有元数据、封面和整文件上传，没有现有条目列表或条目级删除。

5. **多正则文件上传被缩为单文件。**
   - legacy 支持多选、拖入追加、去重和合并。
   - staging `App.tsx:576-589,764-772` 只取 `files?.[0]`，没有 `multiple` 或文件集合管理。

### P1：审核工作区

6. **审核详情缺少风险解释和源码定位。**
   - legacy `modal/admin-review.ts:129-319,419-535` 展示 findings 分组、风险证据、动态／静态目标、源码跳转、重新检查、Markdown／LLM 导出，并对机器阻断要求人工批准确认和具体理由。
   - staging `App.tsx:1529-1607` 主要是状态字段、原始 JSON 折叠、计数和审核按钮。

7. **Diff 从内容对比缩水为计数和名称。**
   - legacy `render/review-diff.ts:1-150` 支持新增／修改／删除、字段和正文差异、未修改项折叠后按需加载、Diff／完整内容切换。
   - staging `App.tsx:1549-1586` 只显示 accepted／changed／added／removed 计数和最多 12 个条目名称。

8. **审核队列操作减少。**
   - legacy 支持 oldest/latest、项目类型过滤、风险信号、连续审核上一条／下一条和已加载／未加载数量。
   - staging `App.tsx:1288-1527` 是简单列表、cursor“加载更多”和状态／gate 行，没有同等队列工具。

### P2：管理员工具

9. **旧版管理员操作日志、当前精选和管理员名单管理缺失。**
   - legacy `modal/admin-tools.ts:1-130` 有操作日志／当前编辑精选、添加管理员、移除管理员及确认。
   - staging `AdminTools.tsx:56-74,181-472` 有站点、项目、成员角色、精选、基线和审计事件，但没有旧版管理员名单与对应日志入口。新角色模型不是旧功能的完整等价替代。

10. **精选删除缺少确认。**
    legacy 对移除操作有 `confirm()`；staging `AdminTools.tsx:190-199,371-378` 直接调用删除，没有同类防误触确认。

## 三、当前代码已明确保留的能力

不能把所有差距都写成“新版什么都没有”。当前 staging 代码仍有：

- 项目列表、搜索、排序、类型／作者／标签筛选。
- 登录、我的项目、草稿保存、创建 revision、删除项目。
- 世界书、正则、封面上传和提交审核。
- 提交 revision 冻结、需新版本后再编辑。
- 已发布展示信息／封面独立修改。
- 本地 Checker 的 pass／warn／block 门禁。
- 审核队列、详情、Diff 计数、文件下载、通过／拒绝／重新检查。
- 点赞、订阅、下载和 staging SillyTavern 消息桥接代码。

这些“存在”不等于与旧版工作流等价；上面的具体差距仍然成立。

## 四、优先级建议

### 新站可用性问题

1. staging 移动详情封面在 `390px` 视口存在已观察到的溢出，应纳入新站自身的可用性优化；不以还原旧版布局作为修复条件。

### 不再作为本轮修复要求

2. 搜索结果、项目版本、条目和互动计数差异：数据尚未同步，本轮不核对或迁移数据。
3. 首页货架和入口差异：属于设计变化，不要求新版恢复旧布局。
4. 条目阅读、上传预览、条目编辑、多正则上传、兼容性确认及完整审核 Diff 等旧功能：作为未来经典版迁移的核对素材，不在本轮自动恢复。缺少现有 API 支持时可以迁前端并用隔离 dummy，最终逐项交用户确认，不反向扩展后端。

### 暂不应混淆

- 旧功能差异不是新版必须恢复的缺陷；当前范围见[双界面迁移决策](../../.agents/notes/in-progress/dual-frontend-migration.md)。
- 未登录导致的用户态内容：本报告只做代码静态判断，不能声称真实账号流程已失败或通过。
- R2 S3 发布故障：已解决，与上述 UI／数据差距无关。
