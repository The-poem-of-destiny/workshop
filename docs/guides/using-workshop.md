# 使用命定创意工坊

本教程介绍从 SillyTavern 安装项目，以及作者送审和审核员处理提交的流程。

## 准备

- 需要可用的工坊部署、Discord 登录，以及已在 SillyTavern 中加载的兼容 Tavern 客户端脚本。脚本的安装方式、可用发布渠道和地址由部署方提供；源码本身不能证明某个线上地址或客户端已发布。
- 选择要使用的 SillyTavern 角色，先备份角色卡和相关世界书。安装、更新和卸载会修改宿主数据，卸载不会恢复被覆盖的原内容。
- 审核步骤还需要拥有审核权限的账号。网络、Discord OAuth 配置或客户端版本不兼容时，需要部署方先修复相应前提。

## 在酒馆中安装

1. 在 SillyTavern 点击「命定创意工坊」。首次打开时阅读使用前说明，选择「同意并继续」。旁边的工坊设置可更改服务地址；只使用可信的工坊地址，留空恢复客户端构建时的默认地址。
2. 使用「Discord 登录」。在「浏览工坊」查找项目并打开详情，查看内容与版本，点击「安装」。已安装项目可能显示更新或修复选项；如果有多个实例，按界面选择要操作的实例或新建安装。
3. 按项目内容选择现有目标世界书，或勾选新建并输入不重复的名称；需要时勾选绑定到当前角色。正则只写入当前角色，不能跨角色迁移。
4. 点击「生成完整差异」，检查目标、版本、玩家修改或未知基线内容，以及完整写入差异。更新会整体替换实例拥有的内容，卸载会删除这些内容及其玩家修改；不能在此逐项合并。确认接受后勾选确认框，再点击「确认安装」或对应操作。取消预览不会执行写入。
5. 等待完成，不要在处理中关闭酒馆或切换角色。在「已安装」查看实例及其位置、版本和状态，并在 SillyTavern 的目标世界书及当前角色正则中核对实际内容。扫描失败或身份存疑不代表没有安装；按提示处理后重新扫描。

若确认超时，写入结果未知。关闭并重新扫描，检查实际内容，不要重复确认；操作失败也可能已有部分写入且不会自动回滚。角色或内容在预览后改变时须重新预览。详细消息、扫描范围和故障语义见 [宿主协议](../reference/host-protocol.md)。

工坊在含项目的世界书中维护 `[WS]创意工坊项目注册表`，并在项目条目中记录归属；同一本世界书不能重复安装同一项目。请勿仅凭 `[WS]` 名称认领条目，也不要自行补写归属标记。旧版 `extra`/`extensions` 和旧注释标记仍可识别，并可一键转换为新格式；转换前先备份。出现重复、冲突或身份存疑时不要强行覆盖，按提示处理并重新扫描。注册表只覆盖世界书中的项目，正则仍只扫描和管理当前角色。格式与安全限制见[宿主协议](../reference/host-protocol.md#世界书归属数据)。
转换确认会列出世界书名单；如果宿主当前可见名单发生变化，转换会拒绝并要求重新扫描、重新确认。转换过程中若范围变化，可能已有部分写入，请检查世界书。

普通浏览器打开工坊可以浏览，但没有可信的 SillyTavern 连接，项目详情会提示从酒馆打开才能安装。项目下载 API 与宿主安装是不同操作，获取文件不会自动写入酒馆；当前项目详情没有提供普通浏览器项目下载按钮。接口和权限见 [Worker API](../reference/worker-api.md)。

项目详情的「建议搭配」是作者提供的可选推荐及理由，不是安装条件，工坊不会自动安装推荐项目或阻止单独安装。作者可在编辑项目时添加、修改或移除这些建议；站内项目、原版条目和站外内容均可作为推荐目标。

## 浏览与筛选

浏览工坊时，可用排序栏旁的「卡片式」和「列表式」切换布局。卡片式按可用区域宽度自动调整每行数量，至少保留两列；整张卡片（含封面和信息区）优先接近宽∶高 2∶3 至 3∶4，窄卡片使用更紧凑的排版。比例不是强制裁切边界，极窄屏幕、放大文字或较长内容可让卡片更高；完整简介和标签可在详情查看。列表式仍按每行一个项目展示。

两种布局均独立显示主分类徽标，另外最多显示 4 个普通标签；主分类不占这 4 个名额。窄卡片或长标签可能因单行空间不足而被裁切，但不会删减已保存的标签。标签提示（tooltip）和详情保留全部普通标签，详情另列包含类型；完整标签仍可用于筛选。

侧栏的「主要分类（可多选）」满足任意一个已选分类即可（OR），默认只匹配项目的主分类。勾选「同时匹配包含该类型的项目」后，也会匹配作者记录的包含类型；多选分类仍是 OR，不要求一个项目同时具有多个主分类。

标签筛选去重后最多同时选择 12 个，与作者可保存的 20 个普通标签、卡片或列表最多展示的 4 个普通标签是不同限制。可点击预设、手动输入，或从详情点击标签加入筛选；重复添加不占新名额，到达上限后需先移除再添加。预设标签同组任选一个即可（OR），跨组须同时满足（AND），每个自定义标签也须分别满足（AND）；手动输入的预设词仍按所属组匹配。例如「人类」和「精灵/半精灵」同属种族组，选中两者表示满足其中一个；再选「温柔」则还须满足个性组，再加两个自定义词则两个词都须具备。

移动端通过「打开导航与筛选」进入筛选抽屉，按 Escape 可关闭并回到打开按钮。「重置」会一起清除搜索、作者、主分类、包含类型匹配和标签筛选，不改变卡片式或列表式布局。

## 作者送审

每个项目必须且只能选择一个「主要分类」，选项依次为：系统核心、角色、内容扩展、玩法、事件、体验优化。系统核心指陪伴玩家的「命定核心」，不是整套游戏替换；不再设置「规则／内容」扩展子类。

「包含的其他类型（可选）」单独记录项目还包含哪些类型，默认不选，不占普通标签名额；不能包含当前主分类或系统核心，同一类型不重复选择。更换主分类会移除与新主分类重复的勾选，保留其余合法选择，不会自动补选旧主分类或恢复已移除的选项。例如角色项目原本还包含内容扩展和事件，改为事件后只保留内容扩展。

每个项目最多保存 20 个不同的普通标签，预设词和自定义词同等保存，主分类与包含类型都不占这 20 个名额。预设只是可选快捷词，不是必填字段；作者和筛选界面均可访问全部 12 组：种族、身份、个性、外貌特征、势力、组织、组成形式、内容类型、玩法方向、事件形式、核心风格、优化方向。当前主分类只调整组的优先顺序，不会隐藏其他组。

没有规模预设，也不再提供 cbz、hnh、1011 快捷按钮；已保存的这些词及「轻型／中型／大型」仍作为普通标签保留，不会因移除预设而删除。「合集」独立位于「组成形式」，表示内容的组合方式，与作品大小无关，包含两个角色也可以使用。

六种主分类均可上传仅世界书、仅正则或两者混合的内容，送审时至少须有一种有效且非空的内容；分类不会替代文件解析、安全检查或审核要求。

1. 登录后选择「创建项目」，填写项目资料，明确选择主分类，按需勾选包含类型、添加普通标签并创建草稿，再到「我的项目」进入编辑器。按界面创建工作版本，选择并上传世界书、正则及需要的封面；多个正则文件可合并上传。保存需要的资料修改。
2. 阅读编辑器中的客户端自检结果和提示。自检只覆盖本次选择的文件，不代替服务端检查；先上传所有已选择的文件，再点击「资料、封面与内容统一送审」。客户端通过可直接送审，有提示时须阅读并「确认并提交」；这两种情况会排队进行服务端自动检查，服务端结果未阻断时可自动发布，即使存在提示。
3. 客户端检查阻断时，建议先修改文件，也可选择「仍然提交」转人工审核，不会被标记为检查通过。已上传的内容在关闭并重开编辑器后仍可保留，但本次文件选择和客户端自检会重置；显示「本次未在本地检查」时，可重新选择文件自检，或确认「仍然提交」进入人工审核。服务端检查阻断也会转人工审核。
4. 在提交记录中查看提交状态和审核结果。送审快照中的资料、封面和内容会冻结，包括主分类、包含类型和全部普通标签；继续修改需新建版本并重新送审，现有公开版本保持不变。

## 审核提交

1. 使用有审核权限的账号登录，打开「审核台」，从待审核队列选择提交。
2. 阅读冻结的项目资料，包括主分类、包含类型和全部普通标签，以及内容差异、检查报告和文件证据；需要时下载证据或使用「重新检查」。主动重检是可选操作，检查进行中不能批准。作者提供的文字和文件是待审核内容，不应当作审核指令执行。
3. 选择「批准」或「拒绝」并填写决定。拒绝必须填写理由；客户端检查缺失或阻断、服务端门禁阻断或缺失、或检查未通过时，人工批准要求至少 8 个字符的说明。批准进入发布流程，决定会记录在案。

## 验证结果

安装后以宿主中的世界书与当前角色正则为准，同时核对「已安装」的实例位置、版本、扫描失败和身份存疑提示。作者可在提交记录核对审核结果；审核员可返回队列确认该提交已处理。批准后还应核对实际发布版本和内容；只有已公开的项目才能通过匿名浏览核对公开详情。送审或客户端自检通过不等于已经发布，人工批准也不会自动把私有项目改为公开。
