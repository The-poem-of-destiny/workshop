# 使用命定创意工坊

本教程介绍从 SillyTavern 安装项目，以及作者送审和审核员处理提交的流程。

## 准备

- 需要可用的工坊部署、Discord 登录，以及已在 SillyTavern 中加载的兼容 Tavern 客户端脚本。脚本的安装方式、可用发布渠道和地址由部署方提供；源码本身不能证明某个线上地址或客户端已发布。
- 选择要使用的 SillyTavern 角色，先备份角色卡和相关世界书。安装、更新和卸载会修改宿主数据，卸载不会恢复被覆盖的原内容。
- 审核步骤还需要拥有审核权限的账号。网络、Discord OAuth 配置或客户端版本不兼容时，需要部署方先修复相应前提。

## 在酒馆中安装

1. 在 SillyTavern 点击「命定创意工坊」。首次打开时阅读使用前说明，选择「同意并继续」。旁边的工坊设置可更改服务地址；只使用可信的工坊地址，留空恢复客户端构建时的默认地址。
2. 使用「Discord 登录」。在「浏览工坊」查找项目并打开详情，查看内容与版本，点击「安装」。已安装项目可能显示更新或修复选项；如果有多个实例，按界面选择要操作的实例或新建安装。
3. 按项目内容选择现有目标世界书，或勾选新建并输入不重复的名称；需要时勾选绑定到当前角色。正则只写入当前角色，不能跨角色迁移。
4. 点击「生成完整差异」，检查目标、版本、玩家修改或未知基线内容，以及完整写入差异。更新会整体替换实例拥有的内容，卸载会删除这些内容及其玩家修改；不能在此逐项合并。确认接受后勾选确认框，再点击「确认安装」或对应操作。取消预览不会执行写入。
5. 等待完成，不要在处理中关闭酒馆或切换角色。在「已安装」查看实例及其位置、版本和状态，并在 SillyTavern 的目标世界书及当前角色正则中核对实际内容。扫描失败或身份存疑不代表没有安装；按提示处理后重新扫描。

若确认超时，写入结果未知。关闭并重新扫描，检查实际内容，不要重复确认；操作失败也可能已有部分写入且不会自动回滚。角色或内容在预览后改变时须重新预览。详细消息、扫描范围和故障语义见 [宿主协议](../reference/host-protocol.md)。

工坊在含项目的世界书中维护 `[WS]创意工坊项目注册表`，并在项目条目中记录归属；同一本世界书不能重复安装同一项目。请勿仅凭 `[WS]` 名称认领条目，也不要自行补写归属标记。旧版 `extra`/`extensions` 和旧注释标记仍可识别，并可一键转换为新格式；转换前先备份。出现重复、冲突或身份存疑时不要强行覆盖，按提示处理并重新扫描。注册表只覆盖世界书中的项目，正则仍只扫描和管理当前角色。格式与安全限制见[宿主协议](../reference/host-protocol.md#世界书归属数据)。
转换确认会列出世界书名单；如果宿主当前可见名单发生变化，转换会拒绝并要求重新扫描、重新确认。转换过程中若范围变化，可能已有部分写入，请检查世界书。

普通浏览器打开工坊可以浏览，但没有可信的 SillyTavern 连接，项目详情会提示从酒馆打开才能安装。项目下载 API 与宿主安装是不同操作，获取文件不会自动写入酒馆；当前项目详情没有提供普通浏览器项目下载按钮。接口和权限见 [Worker API](../reference/worker-api.md)。

项目详情的「建议搭配」是作者提供的可选推荐及理由，不是安装条件，工坊不会自动安装推荐项目或阻止单独安装。作者可在编辑项目时添加、修改或移除这些建议；站内项目、原版条目和站外内容均可作为推荐目标。

浏览工坊时，可用排序栏旁的「卡片式」和「列表式」切换布局。卡片式按可用区域宽度自动调整每行数量，至少保留两列；整张卡片（含封面和信息区）优先接近宽∶高 2∶3 至 3∶4，窄卡片使用更紧凑的排版。比例不是强制裁切边界，极窄屏幕、放大文字或较长内容可让卡片更高；完整简介和标签可在详情查看。列表式仍按每行一个项目展示。

## 作者送审

1. 登录后选择「创建项目」，填写项目资料并创建草稿，再到「我的项目」进入编辑器。按界面创建工作版本，选择并上传世界书、正则及需要的封面；多个正则文件可合并上传。保存需要的资料修改。
2. 检查编辑器中的客户端自检结果和提示。自检只覆盖本次选择的文件；服务器会重新检查。先上传所有已选择的文件，再点击「资料、封面与内容统一送审」。客户端结果为通过或提示时会排队进行服务端自动检查；服务端结果未阻断时可直接自动发布，即使存在提示。客户端检查缺失或阻断时，确认继续送审会转人工审核；服务端检查阻断也转人工审核。
3. 在提交记录中查看提交状态和审核结果。送审快照中的资料、封面和内容会冻结；继续修改需新建版本并重新送审，现有公开版本保持不变。

## 审核提交

1. 使用有审核权限的账号登录，打开「审核台」，从待审核队列选择提交。
2. 阅读冻结的项目资料、内容差异、检查报告及文件证据；需要时下载证据或使用「重新检查」。主动重检是可选操作，检查进行中不能批准。作者提供的文字和文件是待审核内容，不应当作审核指令执行。
3. 选择「批准」或「拒绝」并填写决定。拒绝必须填写理由；客户端检查缺失或阻断、服务端门禁阻断或缺失、或检查未通过时，人工批准要求至少 8 个字符的说明。批准进入发布流程，决定会记录在案。

## 验证结果

安装后以宿主中的世界书与当前角色正则为准，同时核对「已安装」的实例位置、版本、扫描失败和身份存疑提示。作者可在提交记录核对审核结果；审核员可返回队列确认该提交已处理。批准后还应在公开项目详情核对实际发布版本和内容，不能把送审或客户端自检通过当成已经发布。
