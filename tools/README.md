# Repository tools

Development harnesses, repository checks, and data-operation utilities. Command wiring lives in the [root package scripts](../package.json); setup is in the [root README](../README.md).

## Checks and local harnesses

- [Workspace check](check-workspace.mjs) checks repository structure and configuration. [Schema check](check-schema.mjs) replays the [Worker migration chain](../apps/worker/migrations/) into in-memory SQLite and exercises schema invariants; it does not apply remote migrations.
- [Architecture check](../apps/worker/tools/check-architecture.mjs) enforces workspace dependency direction, Web isolation from Worker implementation and storage's type-only data contracts. The separate Worker data-boundary check guards data and storage access from the gateway.
- [Local E2E](e2e-local.mjs) starts a real local Worker with D1/R2 and drives API/browser flows. It seeds and mutates local state, using isolated temporary state by default.
- [Preview debug harness](preview-debug.mjs), launched with `pnpm preview:debug`, starts a local Worker (8800), debug frontend (8801), and simulated hourly recommendation schedule. It initializes local D1 from the migration chain and seeds accounts, subscriptions, author/review examples, and discovery recommendations in `.local/discovery-preview-state` (`PREVIEW_STATE` overrides the directory). Set `PREVIEW_HOST` in the untracked `.env` (see [`.env.example`](../.env.example)) to an address reachable by the browser. This harness mutates local state; stop it with Ctrl+C before loading fixtures.

## Data operations

- [Migration guide](migrate/README.md) covers the local legacy-export converter, verification, local D1 loading, and local asset copying.
- [Legacy preview fixture](dev/load-legacy-fixture.mts) copies selected published projects into disposable local Miniflare D1/R2 state; it bypasses the API and migration chain and is not a complete current-snapshot migration or deployment path. Follow the [review and path instructions](../docs/operations/legacy-data-migration.md#disposable-local-catalogue-preview), explicitly approve every generated review record, then copy [the example configuration](dev/load-legacy-fixture.config.example.json) to `tools/dev/load-legacy-fixture.local.json`. Every relative configured path, including `pythonPath` and `taxonomyReviewPath`, resolves from the source checkout root containing the loader, not the config directory; use absolute original-root Python/private-artifact paths from a worktree. Initialize and stop the preview before running `node --experimental-strip-types tools/dev/load-legacy-fixture.mts`: the loader replaces matching local projects and writes assets directly. Keep source data, reviews and preview state private and untracked; a successful import proves neither complete row/history preservation nor remote object-byte integrity. Miniflare storage paths can change between environments.
- [Backup verifier](backup/verify.mjs) checks local exported project/revision pointers and mirrored asset hashes/sizes. It neither creates a backup nor restores or modifies the live database. Backup and recovery procedures live in the [deployment safety runbook](../docs/operations/deployment-safety.md).
- [Companion version push](push-companion-version.mjs) registers one exact script version through the owner-only HTTP API, then verifies its anonymous exact-version read. Pass `--script`, `--version`, `--name`, `--url` and optionally `--origin`; credentials come only from `WORKSHOP_SESSION_TOKEN`, never `.env`. Defaults to local HTTP; remote registration requires explicit authorization. It records metadata, not script storage or business data.

Application behavior remains in [apps](../apps/README.md); shared schemas, domain rules, and checker implementation live in [packages](../packages/README.md).
