# Migration tools

Use [`offline.py`](../../docs/operations/legacy-data-migration.md) as the sole CLI. Choose the source path before preparing anything:

- **Current-stage SQLite snapshot or SQL dump:** `taxonomy prepare-review --source-kind current`, then `taxonomy build` and the separate `taxonomy verify`. This preserves current-stage additions; do not rebuild an existing stage from an older legacy backup.
- **Original legacy backup:** `taxonomy prepare-review --source-kind legacy`, then the existing `prepare` command with the required `--review`. The full legacy pipeline still checks original object bytes and creates a sealed bounded import plan.
- **Disposable local catalogue preview:** prepare a `--source-kind preview` review for the `projects`/`project_revisions` source, then configure `taxonomyReviewPath` and `pythonPath` using [`load-legacy-fixture.config.example.json`](../dev/load-legacy-fixture.config.example.json). This selects published fixtures for local preview, not a complete current-snapshot candidate or migration acceptance; follow the runbook's [preview path rules](../../docs/operations/legacy-data-migration.md#disposable-local-catalogue-preview).

See the runbook for [working-directory/Python conventions and editable review fields](../../docs/operations/legacy-data-migration.md#review-classifications-locally), including explicit tag repairs. All generated decisions begin unapproved: every record needs both `reviewed` and `tagsAcknowledged` explicitly set to `true`, including direct suggestions and already-canonical values. Unresolved, altered or stale evidence fails closed; tags are never silently truncated. Build creates a fresh candidate-v2 with `verified: false`; run independent `taxonomy verify` separately. Retained imported content exceptions require the runbook's [complete, repeatable `--legacy-provenance` triples](../../docs/operations/legacy-data-migration.md#preserve-verified-legacy-content-exceptions) on both build and verify. These validate original local source/content evidence, not remote R2 completeness. No command here authorizes remote actions, binding changes or production cutover.

For separately authorized staging admission and public-read checks, use `"$PYTHON" tools/migrate/offline.py control {status,close,open,smoke} --token-file <private-token-file>` with the runbook's approved interpreter/path setup. The token file must be an owner-only regular file containing the maintenance token, not a Cloudflare or legacy token. `smoke` also requires `--preparation <validated-private-preparation>` and staging to be explicitly reopened; `--samples` (1–10, default 3) and `--timeout` (1–300 seconds, default 60) are optional. These actions do not replace the active database, and opening admission or exercising staging requires separate authorization.

The legacy transform retains available business snapshots and historical records, reporting explicit omissions. `full-load.py` independently reconstructs every canonical revision/asset column from the original backup and reviewed decisions; `full-validate.py` checks schema and application integrity. The runbook owns [origin authentication, canonical comparison and planner-input boundaries](../../docs/operations/legacy-data-migration.md#preserve-verified-legacy-content-exceptions). The current-snapshot taxonomy path instead copies all logical business rows, changes only reviewed taxonomy/tags and explicitly accounted obsolete fields, and rebuilds derived search. Its verifier checks source-to-candidate non-taxonomy values, relationships, canonical schema/search and integrity independently of the copy operation. The legacy planner freezes inputs and emits bounded batches; the staging executor records durable receipts and never blindly retries ambiguous imports. `full-r2.mjs` remains the sole object transport and checks original bytes before conditionally creating staging objects.

`from_d1_sql.py` is retained solely as an independent public-export utility for the backup verification format; it is not a migration acceptance path. Historical in-place review-report upgrade executors and their duplicate R2 transport are removed; all snapshot objects use `full-r2.mjs` through the sole CLI.
